# Review and Retrieval

Review is an attempt to falsify the learner model.

Use `question-designer`. Do not reread notes as the primary review activity.

## Priority

Review, in order:

1. fragile target generators;
2. known misconceptions;
3. high-centrality prerequisites;
4. concepts due for review;
5. concepts that have never been transferred.

## Delayed assessment design

Use novel wording and altered surface contexts so episodic memory of the lesson is insufficient.

Sample the concept from several angles:

- **meaning** — explain the underlying object/process;
- **motivation** — why is it needed?
- **reconstruction** — rebuild an important relationship;
- **boundary** — when does it stop applying?
- **transfer** — apply it elsewhere;
- **error diagnosis** — reject a plausible wrong model;
- **integration** — connect it to another concept.

One rich question may cover several dimensions.

## No fixed question count

Continue only while another question would materially change the mastery estimate.

Stop when:
- the concept is clearly secure across varied evidence, or
- a specific broken edge has been isolated for repair.

## Retrieval before review

Do not expose the learner to the concept note before the first retrieval attempt.

If retrieval fails:
1. identify the smallest missing cue/dependency;
2. repair it;
3. require a fresh reconstruction;
4. test again later with different wording.

## Update state

- robust novel transfer + reconstruction → secure;
- correct but cue-dependent → fragile;
- partial model → frontier;
- systematic wrong model → misconception + frontier.

Never preserve `secure` because a previous session marked it so.
