# Verify Learning Content

A learning system cannot build trust if it confidently teaches false premises.

## Verification threshold

Verify externally when:

- a factual claim may have changed
- a citation/source matters
- a named theorem, date, benchmark, API, law, or standard is involved
- you are uncertain
- a claim will become a root node for several later deductions

For pure derivations, verify the premises and independently check the algebra/logic.

## Source hierarchy

Prefer:

1. primary sources / official documentation
2. textbooks or authoritative references
3. peer-reviewed papers
4. high-quality secondary explanations
5. forums only for practical experience, not as sole authority

## Separate epistemic types

In notes, distinguish:

- **verified fact**
- **mathematical/logical derivation**
- **interpretation / intuition**
- **heuristic**
- **open question / uncertainty**

Do not present intuition as a theorem.

## Contradiction handling

If verification contradicts something already taught:

1. say so explicitly
2. correct the session note
3. update the concept note
4. identify downstream nodes that depended on the error
5. retest the corrected dependency

Never silently patch a foundational mistake.
